# 异步 Root 设置写入设计

## 目标

消除 OneLab 设置界面因同步等待 `su` 而卡死或触发 ANR 的路径，同时避免子进程输出管道写满导致永久等待。

本次只处理执行线程、输出消费和超时，不调整开关失败回滚、比例页面反馈或其他审核发现。

## 设计

### Shell 命令执行

`Shell` 使用一个统一的内部执行器启动 `su` 命令。执行器持续消费合并后的标准输出和错误输出，并在固定超时时间内等待进程结束。超时后终止进程、关闭流并返回失败；需要输出的调用返回 `null`，只需要结果的调用返回 `false`。

公开方法保持现有返回语义，避免影响系统客户端和诊断代码。内部结果同时携带退出码和输出，避免两套执行路径再次分叉。

### SettingsStore 异步接口

`SettingsStore` 增加面向 UI 的异步写入接口。Binder 直写、root 兜底和写回验证全部在专用单线程执行器中完成，完成回调通过主线程 `Handler` 返回。

单线程执行保证用户连续修改设置时按照点击顺序落盘。同步接口保留给已经明确运行在后台线程的系统客户端和测试使用，但 UI 不再直接调用同步写入接口。

### UI 接入范围

迁移所有由点击、开关、滑块或对话框按钮直接触发的 `SettingsStore` 写入。读取保持同步，因为本地 Settings Provider 读取不涉及 `su` 等待。

现有成功提示与错误提示语义保持不变。本次不新增统一回滚组件；调用方只改为在异步完成回调中执行原本的保存后逻辑。

## 错误处理

- `su` 启动失败、非零退出、读取异常或超时均按写入失败处理。
- 超时进程必须被终止，不能遗留后台子进程。
- 回调只执行一次，并始终在主线程收到。
- Activity 已销毁时不得因回调更新失效 View 而崩溃；页面回调在更新前检查宿主状态。

## 测试

先建立失败测试，再实现：

1. 大量命令输出能够被完整消费，不会阻塞等待。
2. 超时命令在限定时间内返回失败并终止。
3. 正常命令仍保留退出状态和输出语义。
4. 异步设置任务不在调用线程运行，结果只回调一次。
5. 现有设置解析、UI 单元测试、Lint、Debug 和 Release 构建继续通过。

设备验证仅确认安装和应用可启动；不主动触发会改变用户设备设置的每一个开关。
