# 可复用分栏图片全屏组件设计

## 目标

为 OneLab 提供一个可复用的分栏图片全屏能力。组件首次接入小红书，后续可通过独立
Adapter 接入其他应用。小红书接入必须保留原生长按菜单和原生图片切换行为。

## 非目标

- 不重做任一应用的图片加载、缓存或菜单业务；
- 不把小红书的内部类名、资源 ID 或窗口逻辑写进通用组件；
- 不改变没有启用适配器的应用的窗口和 View 层级。

## 分层架构

### `FullscreenImageViewer`

通用组件只负责全屏承载和交互状态：

- 创建/显示/关闭全屏层；
- 保存并恢复进入前的边界、父布局和可见状态；
- 处理返回、双击、缩放和左右滑动的统一生命周期；
- 将长按交给当前 Adapter；
- 在 Adapter 无法接管时安全退出，不显示替代菜单。

组件不引用任何具体应用包名或混淆类。

### `ImageFullscreenAdapter`

每个应用提供独立适配器，负责应用特有能力：

- 判断当前页面是否可接管；
- 取得当前图片 View、图片列表和当前索引；
- 将原始图片 View 接入全屏层并在退出时恢复；
- 接收长按并触发应用原生菜单；
- 报告图片切换和页面销毁，使通用组件及时退出。

Adapter 必须声明能力边界。无法确认原生长按或布局恢复安全时，返回“不支持”，组件
不得模拟一个看似原生的菜单。

### OneLab 控制层

控制层根据总开关、应用子开关和当前包名选择 Adapter。应用列表与白名单取交集；没有
匹配 Adapter 或任一开关关闭时，不安装图片接管逻辑。

## 小红书接入

`XhsImageFullscreenAdapter` 只接管当前详情页中的原始图片 View。全屏层复用该 View，
不复制位图、不重做图片加载。点击图片进入全屏，横向手势继续使用小红书原始
`imageListView` 的切换机制；长按事件回交原始图片 View，由小红书弹出原生菜单。

进入前必须记录原父布局、索引、布局参数、可见性、滚动位置和缩放状态。退出、返回、
页面销毁或接管失败时，Adapter 必须幂等地恢复原布局；恢复失败时优先移除全屏层，避免
遮挡详情页，不强行写入未知父布局。

由于小红书没有独立图片 Activity，Adapter 需要通过结构和行为定位当前图片 View，不能
只依赖单一混淆类名。每次接管前都要确认图片 View 仍属于当前详情页并已完成测量。

## 交互与验收

第一阶段只接受以下结果：

1. 左栏首页和右栏笔记详情保持原状；
2. 点击图片后只有图片跨栏全屏；
3. 左右滑动仍可切换上一张/下一张；
4. 长按弹出小红书原生菜单，而不是 OneLab 自制菜单；
5. 返回或关闭后图片回到原右栏位置，详情页滚动状态不丢失；
6. 接管失败、页面销毁或关闭开关时，不留下覆盖层或悬空 View。

如果第 4 项无法稳定满足，则停止小红书接入，不降级为伪造菜单。酷安继续使用已有的
独立 `PhotoViewV16Activity` 规则，不强行迁移到该 Adapter 体系。

## 测试边界

- 通用组件测试进入/退出状态、重复关闭、返回和能力拒绝；
- 小红书 Adapter 在当前安装版本验证单图、多图、长按、左右滑动、快速返回和详情页
  重建；
- 其他应用在没有专属 Adapter 时验证不触发；
- 不以成功安装或开关状态代替实机 UI 验收。

## 实施顺序

1. 定义通用组件和 Adapter 接口，不接入具体 Hook；
2. 实现小红书 Adapter 的只读定位与能力探测；
3. 在临时实验开关下接入 View 托管和恢复；
4. 实机先验收原生长按，再验收左右滑动和恢复；
5. 通过后才接入正式总开关和应用子开关。
